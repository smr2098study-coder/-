# 段前黑点诊断

## 三种来源

1. 内容字符：`w:t` 中实际有 `•`、`●` 等符号；打印和导出时仍存在。只在确定其为误加符号时删除，不批量删去数学或专业符号。
2. 项目符号列表：直接或继承的 `w:numPr` 指向 numbering 定义，级别的 `numFmt=bullet`；可能使用 Wingdings/Symbol。编号为0表示取消继承编号，不能当作有效列表。检查 numbering 的级别覆盖及样式绑定。
3. 编辑界面的黑方块：Word在显示编辑标记时，用段落左侧小方块提示“与下段同页”“段中不分页”“段前分页”等设置。它不属于文本，一般不进入打印或PDF。用户最新要求正文和标题都取消这些属性，因此本技能也清理标题样式的继承源。

Ctrl+Shift+8可切换Word的编辑标记显示；这只是查看，不修复分页设置。没有实际屏幕或打印证据时，说“OOXML支持此判断”，不要声称已经观察到用户屏幕或所有段落都有黑点。

## 本次真实样本支持的规则

本地样本的主文档共523个段落（含表内段落），508个非空，3个表格；直接 `numPr` 为0，段首实际黑点为0，段落样式中也未发现编号设置。存在79处直接 `keepNext`，其中35处是未分配标题样式的短文本，另有3处表题；10处一级标题通过样式继承 `keepNext` 和 `keepLines`。因此不能把用户所见黑点直接归为AI生成的项目符号。

35处短文本是否是小标题、提纲条目或正文，需按语义和上下文判断，不改变它们的内容及层级。连续条目绑定可造成成块跳页或大片空白，这需要渲染核实。旧版保留标题分页绑定的建议已被用户最新要求替代。此样本只是失败模式证据，不作为新报告的内容模板或格式权威。

## 修复边界

同步清理直接段落属性、样式、继承链及默认值，不仅删除段落上的节点，也不留下 `val=0` 或 `numId=0` 残留。正文及标题都去掉三项分页控制；表图题注也不自动绑定下一段。清除编号属性时保留显式文字编号，不因重套Normal而丢掉标题层级、字号或表格格式。保留真正的分页符及分节符，不更改Word全局显示设置。详细边界见 [清理规则](format-cleanup.md)。
